# Run a prediction from the CLI

`cog run <image> -i name=value ...` starts the built image, runs `setup()`, runs one prediction and prints the output. Inputs are validated against the model's schema on the host, so bad inputs fail with a clear message before any container starts.

## Sub-features

- `run-basic` returns the runner's output for explicit inputs and exits 0.
- `run-default` applies an input's declared default when it is omitted.
- `run-validation` rejects an out-of-range value, a missing required input and an unknown input with exit 1, before the container starts.
- `run-json` accepts all inputs as one JSON object on stdin (`--json @-`) and prints a JSON result object.
- `run-file` reads a file input with `@path` and writes a file output with `-o` (fixture `files`).
- `run-alias` keeps `cog predict` working as a deprecated alias that warns.

## How to get to it (user POV)

- Run `cog run <image> -i key=value` on an image built by Cog.
- Run `cog run -i key=value` in the project directory with no image (builds first).
- Run `echo '{...}' | cog run <image> --json @-`.
- Run `cog run <image> -i file=@input.ext -o output.ext` for file models.
- Run `cog predict <image> ...` (deprecated alias).

## Driving it with cogverify

Preconditions:

- `doctor: OK`; a run with fixture `echo` for every step except `run-file` (which needs its own run with `--fixture files`).
- The image is built: `$V tx --exit 0 --stderr 'Image built as '"$IMAGE" run-prediction--build '"$COG" build -t "$IMAGE" --progress quiet'`.

- **Basic.** Run `$V tx --exit 0 --stdout '^verify:hello verify:hello verify:hello$' --stderr 'Running prediction' run-prediction--run-basic '"$COG" run "$IMAGE" -i text=hello -i times=3'`. The output is the prefix repeated three times and stderr shows `Starting Docker image and running setup()...`.
- **Default.** Run `$V tx --exit 0 --stdout '^verify:hi verify:hi$' run-prediction--run-default '"$COG" run "$IMAGE" -i text=hi'`. `times` was omitted and defaulted to 2.
- **Out of range.** Run `$V tx --exit 1 --stderr 'invalid input "times": number must be at most 5' --stderr-not 'Starting Docker image' run-prediction--validation-range '"$COG" run "$IMAGE" -i text=hi -i times=9'`. Exit 1, no container started.
- **Missing required.** Run `$V tx --exit 1 --stderr 'missing required input "text"' --stderr-not 'Starting Docker image' run-prediction--validation-missing '"$COG" run "$IMAGE"'`.
- **Unknown input.** Run `$V tx --exit 1 --stderr 'unknown input "bogus"; valid inputs are: text, times' run-prediction--validation-unknown '"$COG" run "$IMAGE" -i text=hi -i bogus=1'`.
- **JSON input.** Run `$V tx --exit 0 --stdout '"status": "succeeded"' --stdout '"output": "verify:json"' run-prediction--run-json 'echo "{\"text\":\"json\",\"times\":1}" | "$COG" run "$IMAGE" --json @-'`. Stdout is a JSON object with `status`, `output`, `error` (empty), `metrics.predict_time`.
- **Deprecated alias.** Run `$V tx --exit 0 --stdout '^verify:alias verify:alias$' --stderr '"cog predict" is deprecated, use "cog run"' run-prediction--run-alias '"$COG" predict "$IMAGE" -i text=alias'`.
- **File in, file out (separate run with `--fixture files`).** Build it (`$COG build -t "$IMAGE" --progress quiet`), then run `$V tx --exit 0 --stdout '^HELLO COG$' --stdout '^SECOND LINE$' --stderr 'Written output to: out.txt' run-prediction--run-file 'printf "hello cog\nsecond line\n" > in.txt && "$COG" run "$IMAGE" -i doc=@in.txt -o out.txt --progress quiet >/dev/null && cat out.txt'`, then `$V tx --exit 1 --stderr 'input "doc": open does-not-exist.txt: no such file or directory' run-prediction--run-file-missing '"$COG" run "$IMAGE" -i doc=@does-not-exist.txt'`. `out.txt` on the host holds the upper-cased text; copy anything you want to keep into `$EVIDENCE_DIR` before cleanup (the stdout capture above already does).
- **Proof.** For each step the `.cmd/.stdout/.stderr/.exit/.asserts` bundle; the validation steps' `.stderr` must not contain `Starting Docker image`, which shows the failure happened before a container started (confirm with `docker ps -a --filter ancestor="$IMAGE" -q | wc -l` printing `0` at the end of the validation steps).

## Gotchas

- The prediction result is on stdout and the progress on stderr. With `--json` the result is a JSON object, not the bare value.
- Validation messages are generated by the CLI from the image's schema. If they disappear, check that the build succeeded and that the image carries `run.cog.openapi_schema` (see `build-image`).
- `cog run` containers are removed when the run finishes; a lingering container means a crash or interrupted run. Remove only ones listed by `docker ps -a --filter ancestor="$IMAGE"`.
- `cog run` without an image rebuilds from `cog.yaml` each time; use the image argument to isolate run behavior from build behavior.
- `-o` writes to the host path you give; a relative path lands in `$MODEL_DIR`, which cleanup deletes.
- `cog predict` and `cog run` share one code path today; verifying the alias does not prove `cog run`, and the reverse. Run both when the change touches either name.
- Each step takes about 5 s because setup runs inside an emulated amd64 container on arm64 hosts; do not add sleeps.
